# PoE2 Build Atlas · 技能驱动的配装工坊

**简体中文** · [English](README.en.md) · [日本語](README.ja.md)

[![CI](https://github.com/shihongyue2022/PoE2-Build-Atlas/actions/workflows/ci.yml/badge.svg)](https://github.com/shihongyue2022/PoE2-Build-Atlas/actions/workflows/ci.yml)
[![License: AGPL-3.0](https://img.shields.io/badge/License-AGPL--3.0-blue)](LICENSE)

面向《流放之路 2》国际服的聚合工坊，将 PoB2 角色与技能组合分析、词缀资料、官方交易、装备比较和制作工具接成连续流程。工坊组织原生伤害计算的结果，让词缀与整件装备的贡献可以直接衔接到市场检索和换装决策。

**读取角色与技能组合 → 计算词缀和装备贡献 → 选择保留属性 → 生成官方检索 → 比较整套换装 → 衔接购买或制作。**

官方交易接收已经定义好的条件；工坊把条件之前的角色与贡献分析、条件之后的候选比较也连接起来。伤害计算复用 PoB2，挂牌通过官方交易检索，制作沿用上游引擎；主要开发工作是数据、计算调用、结果组织与操作之间的聚合。

界面支持简体中文、English 与日本語；物品文本解析支持英文、繁体和简体中文，资料匹配与交易检索使用原生英文和官方属性 ID。游戏内可按 **Alt + E** 快捷查价。

### 界面语言 / Interface language / 表示言語

右上角可切换 **简体中文 / English / 日本語**，本地版与浏览器版共用离线语言包。
也可通过 `?lang=en`、`?lang=ja` 或 `?lang=zh-CN` 直接打开指定语言；链接参数优先于本浏览器保存的偏好。
切换即时生效，保留装备、输入草稿、制作计算和账本，不需要重新导入角色。

语言切换只影响界面，不改变物品解析与交易标识。日语游戏内复制文本暂未支持，但日语客户端角色也可从 PoB2 XML／分享代码导入。日语显示优先使用已核对的游戏专名，未确认时保留原生英文；资料原文、诊断信息和部分旧详细说明仍保留原语言。

文案在仓库内维护，不使用外部翻译服务。编辑 `src/workbench/data/ui/copy.tsv` 后运行
`npm.cmd run i18n:build`，生成英文与日文 JSON。语言层只在界面输出处调用，不修改解析结果、交易 ID、
Worker 请求、物品原文或账本金额；未收录的文案保留原文，不猜测机制。

语言回归会展开四个工作区的帮助内容，检查制作样例、XML 上传预览与确认导入后的界面。
文件选择控件使用应用文案，不随浏览器自身语言显示原生按钮；原始装备文本和文件名仍保留原文。
装备词缀使用完整装备词表恢复原生英文，再匹配已核对的日语；升级搜索逐项翻译条件摘要。
语言回归包含 Morior Invictus 六项核心属性检索，并核对切换语言前后的官方查询链接不变。
运行 `npm.cmd run test:workbench:languages`，可用 `WORKBENCH_URL` 指向本地预览或已部署版本。

日语游戏专名与词缀已按 [PoE2DB 日语资料](https://poe2db.tw/jp/) 校对，优先采用同条目 URL、同词缀身份的对应原文；
例如崇高石使用「高貴なオーブ」、混沌石使用「カオスオーブ」、预兆使用「お告げ」。
英文保留游戏／PoB2 的原生名称，不经中文转译。对应词表、核对方法与来源见 [日语词表来源](src/workbench/data/ui/SOURCES.md)。

> 本地版已支持通过 PoB2 原生引擎逐词缀重算，查看当前套装对指定技能的边际伤害贡献。装备检索与候选方向分仍不等于 DPS；完整技能循环、覆盖率和候选换装优化尚未自动重算。

**[直接打开浏览器版](https://shihongyue2022.github.io/apps/poe2-companion/)**：运行实际工坊，支持上传 PoB2 XML／分享代码、技能组、装备比较、官网检索条件及制作计算。自动读档、桌面快捷键、日志、后台挂牌与成交同步需要下方本地版；在线记录保存在当前浏览器，与本地版不自动同步。

## 启动

需要 Windows 和 Node.js **20.19+ 或 22.12+**。导入官网角色还需安装 Path of Building（PoE2）；官方成交同步可选安装 Chrome／Edge 同步扩展。

```powershell
git clone https://github.com/shihongyue2022/PoE2-Build-Atlas.git
cd PoE2-Build-Atlas
npm.cmd ci
.\start-workbench.cmd
```

也可安装 Node.js 后直接双击 `start-workbench.cmd`，首次会自动安装依赖。启动器打开本地网页和快捷键助手，默认地址为 <http://127.0.0.1:5173/?companion=1>。

- `start-workbench.cmd`：启动网页与快捷键助手；关闭启动窗口后服务继续运行。
- `start-hotkeys.cmd`：启动快捷键助手，并确保工坊已运行。
- `stop-workbench.cmd`：停止本项目后台服务；快捷键助手可从托盘退出。

## 日常配装流程

### 1. 读取角色当前状态

在「角色装备」打开 PoB2，进入 **Import/Export Build**，通过官网授权导入角色的天赋、珠宝、装备与技能，再按 **Ctrl + S** 保存。回工坊点「保存后重新读取」，预览变化并确认导入；也支持 PoB2 代码或 XML 文件。

游戏中换装后，需要重新导入 PoB2，再保存、读取。取下装备、药剂或护符时，在 PoB2 勾选 **Delete equipment** 后导入，让空栏覆盖旧装备。仅保存旧文件不会取得游戏最新状态。

工坊会检查来源文件保存时间，并展示更新前后差异。武器组 I／II 分开选择，只有当前组主副手与共同装备参与汇总；缺少对应面板基准时显示未知，不借用另一武器组的数值。

### 2. 定义实际输出技能组

在「输出技能组」点 **＋**，从技能库拖入实际使用的技能，拖动排序或移出；手机可点击添加，用箭头调整顺序。点击技能图标才展开其辅助、联动、词缀与部位资料。

**实际技能组、装备检索重点和 PoB 保存的主技能分别记录。** 查阅技能不会自动改动配装或检索重点；需要围绕该技能找装备时，点击「作为装备检索重点」。

PoB 保存时的单技能伤害只在「输出技能组 → 来源与校验 → PoB 原始快照与装备构成」中核对，不单独作为日常操作入口；补读旧技能资料和 XML 的入口也在这里。

「按默认开始」应用以下规则；已定义的非空技能组会保留：

| 规则 | 默认行为 |
| --- | --- |
| 输出场景 | Boss 持续输出；场景与联动覆盖状态作为待验证条件记录 |
| 技能与辅助 | 保留导入的辅助配置；当前资料齐全时可采用旋风主输出、爆炸长矛地面联动、回旋斩制造旋风的组合 |
| 换装范围 | 联动换两件，四抗检查最终整套 |
| 购买预算 | 默认不限，可选预算档位；合计购买成本，不抵扣尚未售出的旧装 |
| 传奇保护 | 保留已穿传奇身份及已识别机制，允许同名更好 roll；换成其他装备前可解除对应部位保护 |

其他 BD 可自行选择实际技能组，三技能预设仅在导入资料中存在对应技能时提供。

### 3. 查联动、词缀和出现部位

展开技能，核对自身标签、辅助适用条件、伤害转换和联动要求，再查看可检索词缀、出现部位、已核对的前后缀与阶层范围。详情附英文资料与数据来源，未确认的机制保留提示。

选择词缀、部位与阶层，点击放大镜进入装备检索。辅助、条件词缀、技能等级与伤害转换不能简单相乘；范围或投射物速度也不会无条件视为伤害。

本地版可展开技能组下方的 **「全身伤害词缀排行」**，选择组合内的输出技能，点「计算全身词缀贡献」。工坊使用 PoB2 v0.23.1 的本机引擎，保持整套、天赋、辅助及已保存配置，每次移除一条装备词缀重算，并按 DPS 损失降序排列。紧凑表格可多选词缀，点击「搜部位」直达官方市场：同部位同时满足，跨部位分别检索；默认不低于当前数值，也可选 +3%／+5% 或只查存在。传奇保留同名，未映射的词缀不生成条件；衣服图标定位来源装备。

分析菜单与上方已选技能组同步，包含弹幕等主动增益。选择弹幕后，再选「作用于」的可重复弓／投射物长矛输出（如旋风），查看联动配置下该输出的装备词缀贡献；不生成弹幕自身 DPS。移出组合的主动增益不会继续带入重算，PoB 已保存的常驻增益仍保留。重复伤害、狂怒球与冷却沿用原生配置，不推算完整实战循环。没有兼容输出时说明原因并禁用计算。

排行按装备分组：外层按同时移除本件全部词缀的重算损失降序，保留底座／品质／孔数；组内按单条词缀贡献降序。装备汇总独立计算，不累加共享乘区下的单条贡献。各组可折叠、全选检索，零／负向与待核对项归入对应装备；含未解析词缀的汇总标为“已算部分”。

天赋珠宝也支持单条与联合市场检索：按当前 PoB 天赋方案的插槽定位原珠宝，保留准确英文底座，使用词缀自身的数值作为门槛。例如时迭珠宝的“范围内天赋额外获得 2%”按 2% 检索，不使用叠加后的贡献率；不同珠宝分别查询。无法核对来源或官方属性的词缀仍禁用，并显示原因。

首次会保存只含计算数据的 XML 快照；已有本机来源可自动补读同一份未变更存档。装备变化后须先在 PoB 更新、保存并重新导入。无法解析、不能独立移除或移除后技能失效的效果显示待核对，不计作零收益。损失率不能相加成 100%，各输出技能分别计算，不假设完整循环。此功能需 Windows 本地版与已安装的 PoB2；在线版不会用方向评分冒充贡献。

### 4. 围绕核心属性检索装备

装备页的「寻找这件的升级」与「估价这件装备」统一进入核心联合检索：

- 每行选一个属性，再选与当前相同或更高、只查相同，或正向提升百分比；多个核心条件必须同时满足。
- 可以加入物品等级。腰带提供已核对词池中的常用属性，以及可用的 T3／T2／T1、物等和护符栏位档位，尽量减少手填。
- 点 **↓** 指定一个降序优先属性，先观察核心数值对应的市场档位；其他条件继续保留。
- 点「检索提升候选」，在既定门槛与预算内按价格升序找候选，再逐件核对核心值、价格和整套抗性缺口。

查价以**核心属性相近的逐件挂牌**为参考，不把一批不同 roll 的低价物品混成均价，也不混算不同通货。挂牌价不能代表实际成交价。

### 5. 核对整套，再采用组合

候选点「比较这件」会返回对应角色栏，并自动把物品与公开报价加入「候选组合」。继续检索另一部位，即可核对一件或两件组合的总购买成本和最终整套四抗。

**抗性约束作用于整套。** 火、冰、雷与混沌分别计算，全元素抗性不包含混沌；溢出抗性不增加伤害方向分。单件掉抗可保留为待组合候选，由另一部位补齐；「只换这一件」才固定其他部位施加单栏门槛。

面板未知、报价缺失、币种不符或报价超过一天时需要复核，不按零成本或已达标处理。角色装备、武器组或面板基准改变后，旧候选池失效。

「采用此组合」会重新核对约束，通过后一次更新工坊内的装备记录；不会替你交易、修改游戏装备或写回 PoB2。采用后应在 PoB2 重算，并与游戏面板核对。

## 其他功能

| 功能 | 用途与范围 |
| --- | --- |
| 技能与装备构成 | 查看导入的技能、辅助、可读取的伤害快照及装备贡献；未重算内容与快照来源分开标示 |
| 快捷查价 | 游戏内 Alt + E；装备走核心检索，地图、宝石、通货和材料按类型查价 |
| 制作策略 | 复制成品参考 → 调查底装和词池 → 调整目标属性／阶层 → 购买并导入实际底装 → 核对后计算通货、预兆及分支 → 逐步制作核对；已识别部位可研究，成本与执行支持戒指／项链 |
| 交易追踪 | 官方可读成交同步、密语交易线索、CSV 导入导出、按币种统计收支；未售资产估值变化单独展示 |

官方成交同步需首次加载项目自带的 Chrome／Edge 扩展。工坊入口为「交易追踪 → 官方成交同步 → 打开扩展安装入口与目录」，按 [同步桥安装说明](browser-extension/official-history/README.md) 完成后刷新工坊与官网历史页，正常登录官网，再同步。

制作页默认从成品样例规划，与角色配装、现有制作项目分开保存。先调整目标并购买底材，再粘贴实际底装、点击「核对底装」，通过后才可生成制作手顺。计算使用真实物等、稀有度、已有词缀和破裂锁定，不再代入假设的空白底装。底装文本草稿会保存，刷新后需重新核对；更换底装、目标或机制后旧结果失效。路线使用本地 Worker 比较具体通货、预兆及随机结果分支，成本仅显示材料期望、不含底装买价，目标保证阶层要求而非指定 roll。计算后可沿用已核对底装进入逐步制作锚点流程。

选好目标后，可在词缀表下直接「按已选词缀购买」：复用官方查价的联合条件，同底座、所需物等、未腐化／未复制，按价格升序打开官网。属性最低值取所选阶层的原始范围下限，范围伤害按官网平均值检索；不要求随机稀有名称。取消次要目标可找带部分词缀的底材，也可选择「仅按底座购买」。底座搜索默认包含白／蓝／黄非传奇，可单独选稀有度；额外提高物等后会提供按目标最低物等搜索的入口，不自动降低制作要求。更改属性或阶层即更新链接；未核对的映射会阻止联合链接，不会静默丢条件。底座资料读取不代表当前赛季有挂牌；购买结果的实际阶层、品质增幅与空余词缀仍需核对，买到后粘贴真实文本再规划制作。

目标词缀使用紧凑条目表：点击「添加词缀条目」，逐行选择前／后缀、属性分类、具体词缀和阶层，也可停用或删除条目。属性按点伤、增伤、速度、暴击、抗性、生命、魔力、防御等分类，菜单内再按普通、精华、完美精华、合金、亵渎、符文来源分组；仅提供当前底座真实词池中的候选。范围与来源说明按需展开。编辑结果自动保存，删除条目不改变原始成品参考，可一键恢复样例词缀；空白或冲突条目不会被静默跳过。

准备手顺采用编号与箭头连接的官方材料图标卡片。点击图标选用材料，每种材料可直接填写数量或用加减按钮调整，实时显示单步小计与材料总预算；单价优先使用同赛季本地价格表，缺价可展开补填。未选材料不计入，已选材料缺数量／单价时只显示已计价部分。预算按成品样例和赛季单独保存，刷新可恢复；它是用量乘单价的预算，不含底装买价，也不自动叠加下方求解器的随机期望成本。

先看成品参考，再从实际底座词池替换／新增目标。各阶层展示所有数值范围、所需物等、样例物等上限与更高物等上限，并检查前后缀槽位、同组互斥及精华／合金数量。品质、破裂与亵渎历史独立展示，不误当作原始词缀阶层。裂痕戒指附有查阅过的社区实作、游戏数据来源和品质准备步骤；普通与精制底座分别处理，品质、破裂和洗 roll 不混入词缀成本。其他部位只有在原生英文底座唯一匹配本地池时才允许研究，尚不生成通货成本或执行策略。详见 [制作调查方法与裂痕戒指实例](docs/CRAFTING_RESEARCH.md)。

高级复制中的「已工艺／已工藝／Crafted」组头和「无法变动的值／Unscalable Value」说明可直接读取；保留实际 roll，并按真实来源计入工艺词缀限制。例如增加 29% 变动抗性词缀大小会识别为君主合金的 20–30% 前缀。数值说明不会误判为整件装备不可修改；未知词缀仍需核对。

同步只覆盖官网实际返回的近期成交，逐次显示时间范围、买卖方向与条数并去重；**尚未验证用户账号的买入覆盖及可追溯时长，不保证完整历史**。未读到买入不等于没有支出，缺少已确认支出时不把收入当作净利润。密语是报价线索，确认实际成交后才入账；跨来源重复仍需核对。

## 数据与能力边界

| 项目 | 当前行为 |
| --- | --- |
| 角色来源 | 读取 PoB2 保存资料，不直接读取游戏内存；更新游戏角色后需重新导入并保存 |
| 武器组与面板 | 当前武器组独立核对装备贡献和可用基准；尚未完整重算专属天赋、精魂预留、持续增益与最终技能伤害 |
| 联动换装 | 在最多 24 件已收集候选中枚举一件／两件组合；「整套规划」可逐步调整，不是全市场、多部位全局最优求解 |
| 词缀与制作资料 | 使用仓库规则及资料快照，不能保证自动适配游戏新补丁；未知内容保留原文，不视为零收益 |
| 本地记录 | 配装、候选、报价与账本主要保存在当前浏览器；清理网站数据或换浏览器不会自动迁移，建议定期导出支持备份的记录 |

官网登录由官网处理，同步桥不读取或保存 Cookie、口令。本机 PoB2、个人角色文件、日志、凭据、依赖与构建产物不随仓库提供。

## 开发与验证

```powershell
npm.cmd run dev
npm.cmd run type-check
npm.cmd run test:workbench
npm.cmd run build
```

启动本地工坊后，可运行隔离样例的浏览器回归：

```powershell
node scripts/workbench-skill-recommendation-regression.mjs
node scripts/workbench-default-workflow-regression.mjs
node scripts/workbench-craft-blueprint-regression.mjs
```

前者验证技能组操作与词缀检索通路，后者验证市场报价回流、两件补抗、总预算与组合采用。更多验证说明见 [日常操作通路](docs/WORKFLOW.md#验证)。

开发服务器与 `npm.cmd run preview` 提供本地 API；单独静态托管 `dist` 无法提供本机 PoB2、日志读取与后台查价能力。

静态托管可设置 `VITE_WORKBENCH_HOSTED=1`，并用 `VITE_WORKBENCH_BASE=/apps/poe2-companion/` 指定挂载路径后构建。此模式不探测访问者的本机服务，将交易查询交给生成的官网链接。构建产物仍是实际应用，不是案例示例；本地版构建不设置这些变量。
