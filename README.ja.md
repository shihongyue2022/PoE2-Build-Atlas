# PoE2 Build Atlas · スキル起点の装備工房

[简体中文](README.md) · [English](README.en.md) · **日本語**

[![CI](https://github.com/shihongyue2022/PoE2-Build-Atlas/actions/workflows/ci.yml/badge.svg)](https://github.com/shihongyue2022/PoE2-Build-Atlas/actions/workflows/ci.yml)
[![License: AGPL-3.0](https://img.shields.io/badge/License-AGPL--3.0-blue)](LICENSE)

『Path of Exile 2』国際版向けの統合工房です。PoB2のキャラクター・スキル構成分析、モッド資料、公式トレード、装備比較、クラフトを一連の操作に接続します。ネイティブ計算の結果を整理し、モッドと装備全体の寄与から市場検索や交換の判断へ進めます。

**キャラクターとスキル構成を読込 → モッド・装備の寄与を計算 → 残す属性を選択 → 公式検索を生成 → 装備全体で比較 → 購入・制作へ接続。**

公式トレードは指定済みの条件に合う出品を探します。工房は検索前のキャラクター・寄与分析と、検索後の候補比較をつなぎます。ダメージ計算はPoB2、出品検索は公式トレード、クラフトは上流エンジンを利用します。主な開発は、各ツールのデータ、計算呼出し、結果、操作間の受け渡しの統合です。

表示言語は簡体字中国語・英語・日本語に対応します。アイテム文の解析は英語・繁体字・簡体字に対応し、資料照合と取引条件には英語原名と公式属性IDを使用します。ゲーム内では **Alt + E** で価格確認を開けます。

## 表示言語

右上で **简体中文 / English / 日本語** を切り替えます。ローカル版とブラウザー版はオフラインの言語カタログを使用します。

リンクに `?lang=en`、`?lang=ja`、`?lang=zh-CN` を指定することもできます。URLの指定はブラウザー内の保存設定より優先されます。切り替えても装備、入力中の内容、クラフト計算、台帳を維持します。

日本語のゲーム内コピー文の解析は未対応ですが、日本語クライアントのキャラクターもPoB2のXML／共有コードから読み込めます。確認済みの日本語ゲーム用語を優先し、未確認の専名は英語で表示します。資料原文、診断情報、一部の旧詳細説明は元の言語を維持します。

文案は `src/workbench/data/ui/copy.tsv` で管理し、`npm.cmd run i18n:build` で英語・日本語JSONを生成します。表示変換は解析結果、取引ID、Workerリクエスト、アイテム原文、台帳の金額を変更せず、ユーザーデータを外部翻訳サービスへ送りません。

装備の表示文は完全な装備語彙から原語の英語へ対応付け、確認済みの日本語表現と照合します。ファイル選択の表示はアプリの言語に従い、ファイル名と装備原文は変更しません。言語回帰では展開したヘルプ、XML読込、装備検索、公式検索リンクの維持を確認します。`npm.cmd run test:workbench:languages` を実行し、`WORKBENCH_URL` でプレビューや公開版を指定できます。

日本語の専名・モッドは [PoE2DB日本語資料](https://poe2db.tw/jp/) の同一項目URL・モッド識別情報で確認しています。対応方法と出典は [用語資料](src/workbench/data/ui/SOURCES.md) を参照してください。

**[ブラウザー版を開く](https://shihongyue2022.github.io/apps/poe2-companion/?lang=ja)**：PoB2 XML／共有コードの手動読込、スキル設定、装備比較、公式検索生成、クラフト計算に対応します。PoB2による寄与再計算、自動ファイル読込、デスクトップ操作、ログ、出品のバックグラウンド取得、取引同期はローカル版が必要です。両版の記録は自動同期されません。

## ローカル起動

WindowsとNode.js **20.19以降、または22.12以降**が必要です。ゲームのキャラクターを取り込むにはPoE2版Path of Buildingも使用します。公式取引履歴の同期には付属のChrome／Edge拡張を任意で導入できます。

```powershell
git clone https://github.com/shihongyue2022/PoE2-Build-Atlas.git
cd PoE2-Build-Atlas
npm.cmd ci
.\start-workbench.cmd
```

Node.jsの導入後に `start-workbench.cmd` をダブルクリックしても起動できます。初回は依存関係を導入し、ローカル画面とホットキー補助を開きます。既定のアドレスは <http://127.0.0.1:5173/?companion=1&lang=ja> です。

- `start-workbench.cmd`：工房とホットキー補助を起動。起動ウィンドウを閉じてもサービスは継続します。
- `start-hotkeys.cmd`：工房の起動を確認し、ホットキー補助を開始します。
- `stop-workbench.cmd`：本プロジェクトのバックグラウンドサービスを停止。ホットキー補助はトレイから終了します。

## 日常の装備検討フロー

### 1. 現在のキャラクターを読み込む

キャラクター装備欄からPoB2を開き、**Import/Export Build** で公式サイト認証を行い、パッシブ、ジュエル、装備、スキルを取り込みます。**Ctrl + S** で保存し、工房へ戻って保存後の再読込を選び、差分を確認して確定してください。共有コードやXMLファイルにも対応します。

ゲーム内で装備を変えた後は、PoB2で再インポートし、保存・再読込します。装備、フラスコ、チャームを外した場合は **Delete equipment** を有効にして、空きスロットで旧装備を上書きしてください。古いファイルを保存するだけではゲームの最新状態を取得できません。

工房は保存日時と更新前後の差分を表示します。武器セットI／IIは独立し、現在のメインハンド・オフハンドと共通装備だけを集計します。対応する基準値が不明なら、別セットの値を借りず不明として表示します。

### 2. 実際に使用するスキル構成を定義

スキル構成欄で **＋** を押し、ライブラリーから使用するスキルをドラッグします。並べ替えや削除もドラッグで行い、スマートフォンではタップで追加し矢印で順序を変えます。アイコンを選ぶとサポート、連動、モッド、出現部位を確認できます。

**実際の構成、装備検索の重点、PoB保存時のメインスキルは別々に記録します。** 詳細閲覧だけで装備や検索重点は変わりません。そのスキルを軸に装備を探す場合は、検索重点にする操作を選んでください。

保存時の単一スキルダメージは **出典と検証 → PoB元スナップショットと装備構成** で確認します。不足する旧スキル情報やXMLの追加読込もここから行います。

既定設定で開始すると以下を適用し、既に空でないスキル構成は保持します。

| 項目 | 既定の動作 |
| --- | --- |
| 出力場面 | ボスへの継続火力。場面と連動の稼働率は検証条件として記録 |
| スキルとサポート | 読込済みサポートを維持。対応スキルがある場合、ツイスターを主力、エクスプローシブスピアを地面連動、ワーリングスラッシュを旋風の供給元として設定可能 |
| 交換範囲 | 2部位の連動交換を検討し、最終装備全体の4耐性を確認 |
| 購入予算 | 初期は無制限で段階指定可能。未売却の旧装備を購入費用から差し引かない |
| ユニーク保護 | 装備中のユニークと認識済みの仕組みを維持し、同名のより良いロールを許可。別の装備へ変える場合は対象部位の保護を解除 |

他のビルドは構成を自由に選べます。3スキルのプリセットは、読込データに対応するスキルがある場合だけ提示します。

### 3. モッドと装備のダメージ寄与を調べる

スキルのタグ、サポート条件、変換、連動要件を確認し、検索可能なモッド、部位、確認済みの前後モッドやTierを調べます。資料と出典へのリンクも表示します。モッド・部位・段階を選ぶと装備検索へ進めます。サポート、条件付きモッド、レベル、変換を単純に乗算せず、範囲や投射物速度も無条件で火力とは扱いません。

**ローカル版**では、構成の下の装備モッド寄与順位を開き、構成内の出力を選んで計算します。工房は **PoB2 v0.23.1** のネイティブエンジンを呼び出し、装備一式、パッシブ、サポート、保存済み設定を維持してモッドを1つずつ除去・再計算し、DPS損失の降順に並べます。

除去後DPS、差分、損失率を確認し、残したい項目から部位別の市場検索へ進めます。

- 同じ部位の選択モッドは全て同時に満たす必要があり、別部位は個別検索します。
- 現在値以上、+3%／+5%、存在のみの条件を選べます。
- ユニークは同名条件を保持し、未対応モッドは勝手に条件へ変換しません。
- 装備アイコンから元のアイテムを確認できます。

分析メニューは選択中の構成と同期し、**バラージ**などのアクティブバフも含みます。バラージを選んだ場合は、対応する繰り返し可能な弓／投射物スピアの出力、例えばツイスターを作用先に指定します。連動時の出力に対する装備寄与を解析し、バラージ自身の独立DPSは作りません。構成から外したアクティブバフは計算から除外し、保存済みの持続バフは維持します。繰り返し、フレンジーチャージ、クールダウンはPoB設定を引き継ぎ、完全な実戦サイクルは推定しません。対応出力がない場合は理由を表示し計算を無効にします。

結果は装備ごとにまとめます。外側は装備の全モッドを同時に除去し、ベース・品質・ソケット数を保った独立再計算の損失順、内側は単独モッドの寄与順です。共有する乗算や条件があるため、単独の寄与を合算して装備全体の値にはしません。グループの折りたたみ、一括選択、検索ができ、ゼロ／負の寄与と要確認項目も元の装備にまとめます。未解析項目がある合計は部分計算と表示します。

パッシブツリーのジュエルも単独・複合検索に対応します。現在のツリー構成とソケットから元のジュエルを特定し、確認済み英語ベースとモッド自体の値を使います。範囲内パッシブへの追加効果が2%なら、累積した寄与率ではなく2%を検索条件にします。別のジュエルは個別検索し、出典や公式属性を確認できなければ理由を示して無効にします。

初回は計算用データのみのXMLを保存します。変更のないローカル元ファイルから不足情報を再読込できます。装備が変わった場合は先にPoBを更新・保存・再インポートしてください。解析不能、個別除去不能、除去で対象スキルが無効になる効果は要確認とし、ゼロ寄与とは扱いません。損失率は合計100%にはならず、各出力を個別計算します。Windowsのローカル版とPoB2が必要で、オンライン版が方向性スコアを原生寄与の代わりに表示することはありません。

### 4. 重要属性を軸に装備を検索

装備の更新候補検索と価格確認は、同じ重要属性の複合検索へ進みます。

- 各行で1属性を選び、現在値以上、同値、一定割合の向上を指定します。複数の条件は全て同時に満たす必要があります。
- アイテムレベルも追加可能です。ベルトには確認済みの通常属性、T3／T2／T1、必要レベル、チャーム枠の段階を用意します。
- **↓** で降順の基準となる1属性を選びます。他の条件は維持して市場の性能帯を確認します。
- 候補検索では条件と予算を維持して価格の昇順に並べ、各出品の数値、価格、装備全体の耐性不足を確認します。

価格の参考は重要属性が近い個別出品です。異なるロールの安値群を平均せず、為替不明の通貨も混ぜません。出品価格は成立価格ではありません。

### 5. 装備全体を確認してから採用

候補を比較すると該当キャラクタースロットへ戻り、アイテムと公開価格を候補群に追加します。別部位も検索し、1部位／2部位の購入総額と交換後の4耐性を比較できます。

**耐性条件は装備全体に適用します。** 火、冷気、雷、混沌を別に計算し、全元素耐性に混沌は含めません。上限超過分を火力スコアへ加算しません。耐性が下がる単品も別部位で補う候補として保持でき、1部位のみモードでは他の装備を固定します。

ステータス不明、価格欠落、通貨不一致、1日以上前の価格は再確認が必要です。費用ゼロや達成済みとは扱いません。装備、武器セット、基準値が変わると旧候補群を無効にします。

採用時は条件を再確認し、工房内の装備記録をまとめて更新します。自動取引、ゲーム装備の変更、PoB2への書き戻しは行いません。採用後はPoB2で再計算し、ゲーム内の値とも照合してください。

### 公式取引履歴の同期ブリッジ

付属のChrome／Edge拡張を初回に読み込みます。取引追跡から公式履歴同期の拡張導入入口を開き、[導入説明（中国語）](browser-extension/official-history/README.md) に従ってください。工房と公式履歴ページを再読込し、通常どおり公式サイトにログインして同期します。

同期対象は公式サイトが返す最近の取引のみです。各回の期間、売買方向、件数、重複除去を表示します。**ユーザーアカウントでの買入履歴の網羅性と取得可能期間は未確認で、完全な履歴は保証しません。** 買入が見えないことを支出ゼロとは扱わず、支出不明なら収入を純利益とは表示しません。ウィスパーは見積もりで、実際の受け渡し確認後に記帳します。別ソース間の重複は確認が必要です。

### 完成品の目標から実物ベースでの制作へ

クラフトはキャラクター装備と別のプロジェクトとして保存します。完成品を参考に目標を調整し、素材を購入して実物の文章を貼り付け、確認してからルートを計算します。実際のアイテムレベル、レアリティ、既存モッド、フラクチャーを使い、仮定の空ベースに置き換えません。素材の入力文は保存されますが、再読込後は再確認が必要です。ベース、目標、仕組みの変更で旧結果は無効になります。

ローカルWorkerが通貨、お告げ、ランダム分岐を比較します。期待素材費にはベース購入費を含めず、Tierの目標達成は特定ロールの保証ではありません。確認済みベースから1手ごとの実結果確認へ続けられます。

選択モッドでの購入リンクは、同じベース、必要レベル、未コラプト・未ミラー、価格昇順の複合条件を公式サイトへ渡します。下限は選択Tierの元の範囲を使い、範囲ダメージは公式の平均値で検索します。ランダムなレア名は要求しません。副目標を外して一部モッドの素材を探すか、ベースのみを検索できます。ベース検索は通常・マジック・レアの非ユニークを含み、レアリティを指定できます。目標変更でリンクを更新し、未確認の対応は黙って省かず生成を止めます。購入後は実際のTier、品質補正、空き枠を確認してください。

目標はコンパクトな行で前後モッド、属性分類、具体的なモッド、Tierを選びます。フラットダメージ、増加ダメージ、速度、クリティカル、耐性、ライフ、マナ、防御などで分類し、通常、エッセンス、パーフェクトエッセンス、合金、冒涜、ルーンの出現元をメニュー内で分けます。候補は実際のベースプールのみから提示します。無効化や削除ができ、編集を保存しても元の参考装備は変えません。空欄や競合は黙って読み飛ばしません。

準備手順は番号と矢印でつないだ公式素材アイコンで表示します。素材と数量を選ぶと各手順の小計と素材予算を更新します。同じリーグのローカル単価を優先し、不足価格は手入力できます。未選択素材を含めず、数量や単価が欠ける場合は計上済み部分だけを表示します。予算は参考装備とリーグごとに保存し、ランダムな期待費用やベース購入費とは分けます。

Tierには数値範囲、必要レベル、アイテムレベルの上限を示し、前後の枠数、排他グループ、エッセンス・合金の制限を確認します。品質、フラクチャー、冒涜履歴は元のTierと分離します。ブリーチの指輪には参照したコミュニティ例、ゲーム資料、品質準備を付け、通常・精製ベースを区別します。他部位は英語原名がローカルプールに一意対応する場合のみ調査でき、通貨費用や実行ルートは生成しません。[制作調査とブリーチの指輪の例（中国語）](docs/CRAFTING_RESEARCH.md) を参照してください。

詳細コピーのCraftedやUnscalable Valueなどの見出しに対応し、実際のロールと出現元を保持して加工モッド制限に反映します。例えば変動耐性モッドの大きさが29%増加する効果は、対応する合金の20–30%プレフィックスとして認識します。数値の注記を装備全体の変更禁止とは判定せず、不明モッドは要確認とします。

## データと対応範囲

| 項目 | 現在の動作 |
| --- | --- |
| キャラクター情報 | PoB2の保存データを読み、ゲームメモリーにはアクセスしない。ゲーム内変更後は再インポート・保存が必要 |
| 武器セットと基準値 | 現在のセットごとに装備寄与と基準値を確認。専用パッシブ、スピリット予約、持続バフ、交換後の最終火力を完全自動では再構成しない |
| 連動交換 | 収集済み最大24候補から1部位／2部位を列挙。市場全体の多部位グローバル最適解ではない |
| モッドと制作資料 | リポジトリーのルール・資料スナップショットを使用。新パッチへの自動対応を保証せず、未知を効果ゼロとしない |
| 保存記録 | 装備、候補、価格、台帳は主に現在のブラウザー内。サイトデータ削除やブラウザー変更で自動移行しないため、対応する記録は定期的にエクスポート |

ログインは公式サイトで行い、同期ブリッジはCookieやパスワードを読み取ったり保存したりしません。ローカルPoB2、個人のキャラクターファイル、ログ、認証情報、依存関係、ビルド成果物はリポジトリーに付属しません。
